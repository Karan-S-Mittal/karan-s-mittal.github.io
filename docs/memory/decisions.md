# Durable Decisions

These are existing operating decisions inferred from the repository and its design documentation. Change them deliberately and update this file when the decision changes.

## 2026-09-05 — Static-first delivery

Astro static output remains the default. Interactive React is reserved for a mechanism that benefits from direct manipulation, and islands use `client:visible`. Evidence: `astro.config.mjs`, `src/components/visuals/ml/regression/LinearRegressionOLS.astro`.

## 2026-09-05 — One visual language, shared primitives

Instrumented Editorial tokens and `<Exhibit />` are the visual source of truth. New figures should extend shared primitives or the token layer before introducing local styling. Evidence: `docs/design-language.md`, `src/components/editorial/Exhibit.astro`, `scripts/studio-check.js`.

## 2026-09-05 — Representative visual baselines

Visual screenshots cover each layout family at three widths; the full route matrix checks invariants without producing a screenshot for every generated page. This keeps regression evidence useful without multiplying 150 large images. Evidence: `tests/visual/pages.spec.ts`.

## 2026-09-05 — Generated exhibit rasters are build products

Editable exhibit sources stay in source control; raster WebP outputs under `public/generated/` are regenerated by the prebuild and remain ignored. Evidence: `.gitignore`, `scripts/render-exhibits.js`, `package.json`.

## 2026-09-05 — Organisational outcomes anchor the professional identity

The website’s purpose is to establish Karan’s reputation and generate relevant business enquiries. Use engineer-scientist as the professional anchor, with building stable, useful systems and enabling team ownership as the through-line. Founder, educator, and community organiser remain visible parts of that practice. “Deterministic” belongs in the technical context where its guarantee can be stated precisely, rather than standing in for the whole identity.

Present public implementations and documented events as evidence of those specific contributions. Do not recast generic service descriptions as completed client case studies or invent commercial outcomes. Engagement deliverables describe proposed work. Preserve the established Astro/GitHub Pages architecture and editorial visual tokens.

## 2026-09-07 — Visuals Studio, Attribution Stamp, and 3× Export Pipeline

Interactive and static architectural diagrams are organized under `/visuals/` as standalone exhibits with a searchable gallery. Every visual embeds `<VisualAttribution />` for permanent architect provenance in exported assets, featuring a swappable logo slot for client/organizational co-branding. Diagram exports are standardized at 3× ultra-sharp vector resolution (300 DPI equivalent) via `html-to-image` using coordinate locking, native transform scaling, and `document.fonts.ready` synchronization. Evidence: `src/components/diagram/VisualAttribution.astro`, `src/components/diagram/DiagramExportBar.astro`, `src/pages/visuals/index.astro`.


## 2026-09-08 — Simple diagram skill and compact download pages

Karan wants to provide a flow or sketch in conversation and receive a small, reusable visual with authorship and download, also usable in blog posts. This supersedes the 2026-09-07 mandatory showroom/gallery workflow and 300 DPI wording. Maintain one short `diagram-craft` skill, one reusable diagram component, and a tiny route using `VisualPage.astro`; do not add preview pages, duplicate specimens, or registry work unless requested. Existing discovery routes are retained. Default attribution is the monogram and Karan Mittal name inside the artwork. PNG resolution is expressed in pixels at 3×, with scaling applied only once.

## 2026-09-08 — Prune overlapping authoring skills

Keep two canonical repository skills: `diagram-craft` for attributed visuals and `explanatory-studio` for evidence-backed essays. Retain concrete mechanism explanations, consistent entity encodings, readable connector routing, and primary-citation guidance. Remove copied palettes, missing-component catalogs, automatic syndication, and elaborate setup/variant requirements. `CLAUDE.md` routes to these files, while Gemini's two skill entries are filesystem links to the same repository directories. The obsolete Gemini `d3-architectural-diagrams` skill and duplicate essay instructions are retired outside active discovery under `~/.codex/skill-archive/diagram-cleanup-20260908-114510/`.

Keep the global `diagram-design` template/reference library for explicitly independent HTML artifacts; its concise entrypoint excludes the normal Astro studio workflow and overrides old prescriptive defaults in its references. Unrelated installed and bundled skills were not part of this cleanup.

## 2026-09-08 — Username insignia and subject-only labels

Use `karansmittal` as the shared visual signature, replacing the KM monogram and full-name stamp. Keep it inside the capture area and blog component. Remove decorative C4/IEEE method labels from diagram footers and gallery descriptions; visible labels should explain the subject. `VisualAttribution.astro` now renders a small wordmark with optional author/class overrides, without roles, studio lines, or logo variants.

## 2026-09-08 — Retire internal /studio and streamline /visuals/ gallery

Decommissioned the unused internal `/studio/` control room and showroom pages, removing Studio from primary header and footer navigation. Simplified `/visuals/` into a fast, dedicated gallery of architectural visuals where every card points strictly to a standalone inspection and 3× PNG download page (`/visuals/<slug>/`), with zero redirects to blog posts or testbenches.

## 2026-09-08 — Diagram minimalism, vector iconography, and headless inspection

Refined `diagram-craft` skill to enforce pure block-focused architectural diagrams. Omit decorative category banners, method classifications, and runtime footers inside the component canvas. Mandate zero emojis in favor of 1.5px monoline vectors from `@lucide/astro` and `BrandIcon.astro`, supported by `npm run icon <keyword>` (`scripts/find-icon.js`). Added automated headless visual verification via `scripts/capture-visual.js` (`npm run visual:capture <slug>`) to capture dual-theme light/dark screenshots into `test-results/` for inspection before delivery.
