# Durable Decisions

These are existing operating decisions inferred from the repository and its design documentation. Change them deliberately and update this file when the decision changes.

## 2026-09-05 — Static-first delivery

Astro static output remains the default. Interactive React is reserved for a mechanism that benefits from direct manipulation, and islands use `client:visible`. Evidence: `astro.config.mjs`, `src/components/visuals/ml/regression/LinearRegressionOLS.astro`.

## 2026-09-05 — One visual language, shared primitives

Instrumented Editorial tokens and `<Exhibit />` are the visual source of truth. New figures should extend shared primitives or the token layer before introducing local styling. Evidence: `docs/design-language.md`, `src/components/editorial/Exhibit.astro`, `scripts/studio-check.js`.

## 2026-09-05 — Representative visual baselines

Visual screenshots cover each layout family at three widths; the full route matrix checks invariants without producing a screenshot for every generated page. This keeps regression evidence useful without multiplying 150 large images. Evidence: `tests/visual/pages.spec.ts`.

## 2026-09-05 — Generated exhibit rasters are build products

Editable exhibit sources stay in source control; raster WebP outputs under `public/generated/` are regenerated by the prebuild and remain ignored. Evidence: `.gitignore`, `scripts/render-exhibits.js`, `package.json`.

## 2026-09-05 — Organisational outcomes anchor the professional identity

The website’s purpose is to establish Karan’s reputation and generate relevant business enquiries. Use engineer-scientist as the professional anchor, with building stable, useful systems and enabling team ownership as the through-line. Founder, educator, and community organiser remain visible parts of that practice. “Deterministic” belongs in the technical context where its guarantee can be stated precisely, rather than standing in for the whole identity.

Present public implementations and documented events as evidence of those specific contributions. Do not recast generic service descriptions as completed client case studies or invent commercial outcomes. Engagement deliverables describe proposed work. Preserve the established Astro/GitHub Pages architecture and editorial visual tokens.

## 2026-09-07 — Visuals Studio, Attribution Stamp, and 3× Export Pipeline

Interactive and static architectural diagrams are organized under `/visuals/` as standalone exhibits with a searchable gallery. Every visual embeds `<VisualAttribution />` for permanent architect provenance in exported assets, featuring a swappable logo slot for client/organizational co-branding. Diagram exports are standardized at 3× ultra-sharp vector resolution (300 DPI equivalent) via `html-to-image` using coordinate locking, native transform scaling, and `document.fonts.ready` synchronization. Evidence: `src/components/diagram/VisualAttribution.astro`, `src/components/diagram/DiagramExportBar.astro`, `src/pages/visuals/index.astro`.

This supersedes the 2026-09-07 mandatory showroom/gallery workflow and 300 DPI wording.
